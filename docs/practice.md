# Практика и наставники

Рабочий модуль сопровождения практики внутри существующего VK Mini App. Разделы:

- `/#/practice` — практика, контакты, первые дни, цели, встречи, опросы, обращения, результаты, карьерные предпочтения и документы.
- `/#/mentor` — назначенные практиканты, цели, встречи, отзывы и адресованные наставнику обращения.

Админка не добавлялась. Существующий кабинет обработки откликов не изменён. Отклик со статусом `accepted` сам по себе не создаёт практику: выход подтверждает администратор в своей системе.

## Локальная демонстрация

Обычный запуск: `npm ci`, затем `npm run dev`. Откройте `http://127.0.0.1:5188/#/practice` и нажмите «Создать демопрактику». Полный профиль кандидата для этой локальной демонстрации не нужен. Если профиль уже заполнен, он сохраняется.

Будут созданы учебная практика с пятью целями, встречей и отзывом и отдельный аккаунт наставника. Кнопка «Открыть как наставник» переключает локальную сессию; обратная кнопка возвращает практиканта. Предпочтение действует в пределах вкладки, а данные хранятся в SQLite. Повторное создание демо не сбрасывает результаты.

Для проверки собранной версии: `npm run build`, затем `DEV_AUTH=1 npm start`. Адрес: `http://127.0.0.1:3001/#/practice`. Вход в демо ограничен существующей серверной проверкой loopback, Host и отсутствия proxy-заголовков. `/api/practice/demo` дополнительно запрещён для VK-аккаунтов и при `DEV_AUTH!=1`.

## Структура

- `server/practice.py` — схема, миграция, проверка назначений, операции практики и функции подключения админки.
- `src/practice/PracticeApp.tsx` — интерфейсы практиканта и наставника.
- `src/practice/types.ts`, `utils.ts`, `practice.css` — типы, календарь/экспорт, оформление.
- `server/tests/test_practice.py`, `src/practice.test.ts` — роли, приватность, статусы, повторы, календарь и экспорт.

Профиль наставника — отдельная запись `mentors` с уникальной связью `user_id → users.id`. Один наставник может иметь несколько практикантов. Практика хранит текущий `mentor_id`; старые отзывы сохраняют имя автора и его идентификатор после переназначения.

## Подключение внешней админки

Управление назначениями намеренно не доступно через пользовательские endpoints. Если админка использует этот Python backend, после своей авторизации она вызывает функции внутри `Store.transaction()`:

```python
from server.practice import provision_mentor, provision_practice, assign_mentor

with store.transaction() as db:
    mentor_id = provision_mentor(
        db, user_id='vk:MENTOR_ID', name='Имя наставника',
        position='Должность', contact='mentor@example.org',
        about='С чем поможет', office_hours='Пн–пт, 09:00–17:00',
    )
    practice_id = provision_practice(
        db, user_id='vk:STUDENT_ID', mentor_id=mentor_id,
        title='Лаборатория и качество', department='Лаборатория',
        start_date='2026-11-02', end_date='2026-12-11', status='active',
        coordinator={'name': 'Координатор', 'contact': 'practice@example.org'},
        arrival='Главная проходная, 09:00. Возьми паспорт и направление.',
        documents=[{'title': 'Отчёт по практике', 'status': 'В подготовке'}],
    )
    # При смене наставника; None снимает назначение.
    assign_mentor(db, practice_id, mentor_id)
```

Аккаунты `users` должны существовать до назначения. Для отдельного сервиса админки потребуется её собственный защищённый транспорт к этим операциям: он в модуль не входит. Не выдавайте административные полномочия по параметрам пользовательского запроса.

Админка отвечает за обновление периода/статуса в `practices`, статусов `documents`, обработку `practice_requests` с `target='coordinator'` и просмотр `practice_career`. При правке периода нужно сохранять его согласованность с уже назначенными целями и встречами. Не редактируйте SQLite-файл параллельно через несовместимые средства; используйте транзакции и включайте foreign keys.

## HTTP API пользователя

Все маршруты требуют существующую Bearer-сессию. Ответы — JSON. Ошибки используют общий формат `{error, code}`.

| Метод и маршрут | Действие |
| --- | --- |
| `GET /api/practice/bootstrap` | Свои практики и назначенные практиканты; данные отфильтрованы по роли |
| `PUT /api/practice/:id/onboarding` | `{steps: ['arrival','documents','safety','team']}` — выполненные шаги |
| `POST /api/practice/:id/goals` | Наставник: `{title, description, criteria, dueDate, clientKey}` |
| `PATCH /api/practice/:id/goals/:goal` | `{status, version, mentorComment?}` либо наставник: `{title?,description?,criteria?,dueDate?,version}` |
| `POST /api/practice/:id/meetings` | Наставник: `{title, startsAt, endsAt, location, agenda, clientKey}` |
| `PATCH /api/practice/:id/meetings/:meeting` | Наставник: все поля встречи и `version`, либо `{status,version}` |
| `POST /api/practice/:id/feedback` | Наставник: `{body,clientKey}` |
| `PUT /api/practice/:id/checkins` | Практикант: `{answers:{mood?,comfort?,workload?,clarity?,support?,comment?}}` |
| `POST /api/practice/:id/requests` | Практикант: `{target:'mentor'|'coordinator',topic,body,clientKey}` |
| `PATCH /api/practice/:id/requests/:request` | Наставник: `{status,response,version}` — только обращение к наставнику |
| `PUT /api/practice/:id/career` | Практикант: `{interested:boolean,direction,schedule,comment}` |

`clientKey` — стабильный ключ конкретной отправки (8–100 символов: буквы, цифры, `_`, `-`). Повтор одного POST не создаёт вторую запись. `version` берётся из bootstrap; устаревшее изменение возвращает 409. Клиент обновляет данные и предлагает повторить действие.

Цели: `planned → in_progress → review → approved`. Только назначенный наставник подтверждает цель или возвращает её из `review` в `in_progress`. Подтверждённые цели не редактируются. Сроки ограничены периодом практики.

Встречи: `scheduled`, `completed`, `cancelled`. Время передаётся с часовым поясом, хранится в UTC, показывается в Москве. Продолжительность — от минуты до 12 часов. Перенос увеличивает версию; практикант может запросить перенос отдельным обращением.

Завершённая или отменённая практика доступна для чтения, но все новые изменения возвращают 409. Экспорт результатов доступен и после завершения.

## Приватность и границы первой версии

- Наставник получает только назначенные практики. После переназначения доступ прежнего наставника прекращается.
- Опрос добровольный. Оценки — 1–5 или пропуск. На неделю по московскому времени сохраняется один ответ, который можно обновить. Пропуск всего опроса ничего не записывает.
- `checkins` и `career` отсутствуют в payload наставника. Ему также не выдаются обращения координатору. Пользователь может отдельно адресовать наставнику конкретный вопрос.
- Экспорт результатов — локальный текстовый файл с целями и отзывами, без опросов и карьерных предпочтений. Он не заменяет подписанный документ учебного заведения.
- Документы пока представлены статусами. Файловое хранилище, подписи, push-уведомления и автоматические внешние сообщения не подключены.
- Интерес к работе сохраняется для координатора; предложение работы автоматически не создаётся.
- Личные ответы не участвуют в оценке целей или автоматическом принятии кадровых решений. Внешняя админка должна отдельно установить свои права доступа и правила хранения таких ответов.

## Проверка

`npm test` запускает существующие проверки и новые тесты модуля. `npm run build` проверяет TypeScript и производственную сборку. Приёмочный сценарий: демопрактика → опрос → цель на проверку → переключение в наставника → подтверждение цели → возврат к практиканту → просмотр результата.

При разработке пройдены 42 серверных теста и 22 теста TypeScript; TypeScript и производственная сборка прошли проверку. В браузере проверены создание демопрактики, заполнение опроса, отправка цели на проверку и подтверждение наставником, создание новой цели и встречи, сохранение после переключения аккаунтов. Проверены узкий экран (320 px с масштабом браузера) и широкий кабинет; горизонтального переполнения не осталось.

Скриншоты работающей сборки: [практикант](screenshots/practice-home.jpg), [наставник](screenshots/practice-mentor.jpg). На них учебные данные, изменённые в ходе проверки; новая демопрактика начинает с пяти целей.
