# Практика и наставники

Практика и назначения теперь управляются через **Django Unfold `/admin/`** поверх **PostgreSQL**. Формы сотрудников/наставников/практики, история назначений и обработка обращений координатору реализованы; чувствительные опросы и карьерные предпочтения защищены отдельными разрешениями. Подробности: [Django-админка](django-admin.md), [сущности](admin-entities.md), [ORM-манифест](django-models.json). Описанные ниже исходные provisioning/DDL-примеры остаются полезны для тестов и совместимости, но не означают отсутствие административного интерфейса.

Рабочий модуль сопровождения практики внутри существующего VK Mini App. Разделы:

- `/#/practice` — практика, контакты, первые дни, цели, встречи, опросы, обращения, результаты, карьерные предпочтения и документы.
- `/#/mentor` — назначенные практиканты, цели, встречи, отзывы и адресованные наставнику обращения.

Отклик со статусом `accepted` сам по себе не создаёт практику: администратор отдельно подтверждает выход и назначение в Unfold.

## Вход и локальный запуск

На стартовом экране сохранена кнопка «Открыть свой маршрут». Кнопка «Я уже в Очаково» ведёт на `/#/login`. После входа серверная роль направляет в кабинет практиканта или наставника. Регистрации, выбора роли и создания демопрактики в интерфейсе нет.

Создание двух связанных тестовых аккаунтов из терминала:

```sh
python3 -m server.staff_accounts --db .data/ochakovo.sqlite3
```

Команда создаёт пользователей, наставника, назначенную практику, пять целей и встречу. Выданные логины и пароли сохраняются в игнорируемый Git файл `.data/ochakovo-issued-accounts.json` с правами `0600`. Повторный запуск возвращает ранее выданные данные и не сбрасывает пароли или прогресс. Данные для входа передаются пользователям вручную; отправки почты нет.

Запуск: `npm ci`, `npm run dev`; форма входа — `http://127.0.0.1:5188/#/login`. Для собранной версии: `npm run build`, `DEV_AUTH=1 npm start`, адрес `http://127.0.0.1:3001/#/login`. Парольный вход работает также без `DEV_AUTH`; этот флаг нужен только существующему локальному маршруту кандидата.

Пароли хранятся как PBKDF2-SHA256 (600 000 итераций, индивидуальная случайная соль). Сессия живёт 12 часов, токен хранится в sessionStorage отдельно от маршрута кандидата. В базе сохраняется хеш токена. После восьми неудачных попыток для пары IP/логин вход блокируется на 15 минут. Выход отзывает сессию на сервере; отключение учётной записи немедленно закрывает доступ к практике.

## Структура

- `server/practice.py` — схема, миграция, проверка назначений, операции практики и функции подключения админки.
- `src/practice/PracticeApp.tsx` — интерфейсы практиканта и наставника.
- `src/practice/types.ts`, `utils.ts`, `practice.css` — типы, календарь/экспорт, оформление.
- `server/tests/test_practice.py`, `src/practice.test.ts` — роли, приватность, статусы, повторы, календарь и экспорт.

Профиль наставника — отдельная запись `mentors` с уникальной связью `user_id → users.id`. Один наставник может иметь несколько практикантов. Практика хранит текущий `mentor_id`; старые отзывы сохраняют имя автора и его идентификатор после переназначения.

## Подключение внешней админки

Управление назначениями намеренно не доступно через пользовательские endpoints. Если админка использует этот Python backend, после своей авторизации она вызывает функции внутри `Store.transaction()`:

```python
from server.practice import provision_mentor, provision_practice, assign_mentor
from server.staff_auth import provision_account

with store.transaction() as db:
    provision_account(db, user_id='staff:MENTOR_ID', login='mentor.login',
                      password=mentor_password, role='mentor')
    provision_account(db, user_id='staff:STUDENT_ID', login='intern.login',
                      password=intern_password, role='intern')
    mentor_id = provision_mentor(
        db, user_id='staff:MENTOR_ID', name='Имя наставника',
        position='Должность', contact='mentor@example.org',
        about='С чем поможет', office_hours='Пн–пт, 09:00–17:00',
    )
    practice_id = provision_practice(
        db, user_id='staff:STUDENT_ID', mentor_id=mentor_id,
        title='Лаборатория и качество', department='Лаборатория',
        start_date='2026-11-02', end_date='2026-12-11', status='active',
        coordinator={'name': 'Координатор', 'contact': 'practice@example.org'},
        arrival='Главная проходная, 09:00. Возьми паспорт и направление.',
        documents=[{'title': 'Отчёт по практике', 'status': 'В подготовке'}],
    )
    # При смене наставника; None снимает назначение.
    assign_mentor(db, practice_id, mentor_id)
```

Пароли генерирует и передаёт администратор; значения `mentor_password` и `intern_password` в примере поступают из его защищённого процесса. `provision_account` создаёт `users` и `staff_credentials` до назначения, требует пароль длиной 12–256 символов и запрещает повторную выдачу с перезаписью. Для отдельного сервиса админки потребуется её собственный защищённый транспорт к этим операциям: он в модуль не входит. Не выдавайте административные полномочия по параметрам пользовательского запроса.

Админка отвечает за обновление периода/статуса в `practices`, статусов `documents`, обработку `practice_requests` с `target='coordinator'` и просмотр `practice_career`. При правке периода нужно сохранять его согласованность с уже назначенными целями и встречами. Не редактируйте SQLite-файл параллельно через несовместимые средства; используйте транзакции и включайте foreign keys.

## HTTP API пользователя

Практика требует Bearer-сессию активного аккаунта `staff_credentials`; сессия кандидата не даёт доступа. `POST /api/staff/login` принимает `{login, password}`, возвращает `{token, role, userId}`; `GET /api/staff/session` проверяет роль; `DELETE /api/auth` завершает сеанс. Ответы — JSON. Ошибки используют общий формат `{error, code}`.

| Метод и маршрут | Действие |
| --- | --- |
| `GET /api/practice/bootstrap` | Свои практики и назначенные практиканты; данные отфильтрованы по роли |
| `PUT /api/practice/:id/onboarding` | `{steps: ['arrival','documents','safety','team']}` — выполненные шаги |
| `POST /api/practice/:id/goals` | Наставник: `{title, description, criteria, dueDate, clientKey}` |
| `PATCH /api/practice/:id/goals/:goal` | `{status, version, mentorComment?}` либо наставник: `{title?,description?,criteria?,dueDate?,version}` |
| `POST /api/practice/:id/meetings` | Наставник: `{title, startsAt, endsAt, location, agenda, clientKey}` |
| `PATCH /api/practice/:id/meetings/:meeting` | Наставник: все поля встречи и `version`, либо `{status,version}` |
| `POST /api/practice/:id/feedback` | Наставник: `{body,clientKey}` |
| `PUT /api/practice/:id/checkins` | Практикант: `{answers:{mood?,comfort?,workload?,clarity?,support?,comment?}}` |
| `POST /api/practice/:id/requests` | Практикант: `{target:'mentor'|'coordinator',topic,body,clientKey}` |
| `PATCH /api/practice/:id/requests/:request` | Наставник: `{status,response,version}` — только обращение к наставнику |
| `PUT /api/practice/:id/career` | Практикант: `{interested:boolean,direction,schedule,comment}` |

`clientKey` — стабильный ключ конкретной отправки (8–100 символов: буквы, цифры, `_`, `-`). Повтор одного POST не создаёт вторую запись. `version` берётся из bootstrap; устаревшее изменение возвращает 409. Клиент обновляет данные и предлагает повторить действие.

Цели: `planned → in_progress → review → approved`. Только назначенный наставник подтверждает цель или возвращает её из `review` в `in_progress`. Подтверждённые цели не редактируются. Сроки ограничены периодом практики.

Встречи: `scheduled`, `completed`, `cancelled`. Время передаётся с часовым поясом, хранится в UTC, показывается в Москве. Продолжительность — от минуты до 12 часов. Перенос увеличивает версию; практикант может запросить перенос отдельным обращением.

Завершённая или отменённая практика доступна для чтения, но все новые изменения возвращают 409. Экспорт результатов доступен и после завершения.

## Приватность и границы первой версии

- Наставник получает только назначенные практики. После переназначения доступ прежнего наставника прекращается.
- Опрос добровольный. Оценки — 1–5 или пропуск. На неделю по московскому времени сохраняется один ответ, который можно обновить. Пропуск всего опроса ничего не записывает.
- `checkins` и `career` отсутствуют в payload наставника. Ему также не выдаются обращения координатору. Пользователь может отдельно адресовать наставнику конкретный вопрос.
- Экспорт результатов — локальный текстовый файл с целями и отзывами, без опросов и карьерных предпочтений. Он не заменяет подписанный документ учебного заведения.
- Документы пока представлены статусами. Файловое хранилище, подписи, push-уведомления и автоматические внешние сообщения не подключены.
- Интерес к работе сохраняется для координатора; предложение работы автоматически не создаётся.
- Личные ответы не участвуют в оценке целей или автоматическом принятии кадровых решений. Админка применяет отдельные разрешения на личные опросы и карьерные предпочтения; общая staff-роль мини-приложения их не предоставляет.

## Проверка

`npm test` запускает существующие проверки и тесты модуля, `npm run build` проверяет TypeScript и сборку. После объединения с основным приложением проходят 71 серверный и 43 TypeScript-теста, включая вход, выход, блокировку попыток, деактивацию аккаунта, создание связанных пользователей, изоляцию ролей и отсутствие публичного создания демопрактики.

Приёмочный сценарий: стартовая страница → «Я уже в Очаково» → вход практикантом → выход → вход наставником → просмотр назначенной практики. Проверяется сохранение входа после перезагрузки и возврат к авторизации после выхода.


## Сообщество сотрудников

Аккаунт с ролью `employee` входит через общий `/api/staff/login` и попадает в `/#/employee`: материалы, события и мерч. Ему не нужны кандидатская анкета, ранее поданная заявка или назначенная практика. Роли `intern` и `mentor` сохраняют свои кабинеты и переходят из них в `/#/community`. Выдача/отключение employee-аккаунта использует тот же `provision_account`; открытой саморегистрации сотрудников нет.

Сообщество использует существующие ledger, registrations, activity_completions и exchanges. Баллы за материал и очную QR-активность доступны для обмена на мерч; запись на мероприятие сама по себе баллов не даёт. Новая аудитория событий и материалов проверяется сервером, не только интерфейсом. У назначенного активного практиканта есть карточка «Приведи друга» со стабильным личным кодом и счётчиками ожидающей/состоявшейся выдачи мерча. Подробности — [referrals.md](referrals.md).
