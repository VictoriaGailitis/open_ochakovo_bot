# Контент и конструкторы в Django Unfold

Админка находится по `/admin/`. Редактор контента управляет материалами, защищёнными медиа, карьерными предложениями и наградами; редактор игр — семействами, уровнями, приватными правилами, спрайтами и композициями. Публикация уровней требует отдельного разрешения `content.publish_leveldefinition`. Обычные редакторы не удаляют записи и исторические прохождения. Изменения и публикации записываются в операционный аудит без ответов, бинарных файлов и токенов.

## Материалы и тесты

В «Материалах» можно составить последовательность блоков: заголовок, текст, изображение и видео. Редактор добавляет и удаляет блоки и меняет их порядок. Текст хранится как текст и безопасно выводится читателю: HTML и скрипты не исполняются. Изображение/видео выбирается по ID из «Медиа материалов»; файл загружается через форму, а не через поле BLOB. Поддерживаются проверенные PNG/JPEG/WebP, MP4/WebM до 50 МБ. Медиа-просмотр администратора требует сессии и разрешения, в мини-приложении — авторизации и доступа к опубликованному материалу. Аудитория файла должна совпадать с аудиторией материала либо быть `all`.

Конструктор короткого теста содержит баллы, вопросы, варианты, ID правильного ответа и пояснение. Можно переставлять вопросы и варианты. Флажок «Материал без теста» отключает награду. Сервер проверяет уникальность ID, существование правильного варианта, длины и пределы количества вопросов/баллов. Правильные ответы и пояснения хранятся в закрытых вопросах/снимках; публичный API не включает ключи ответов.

Ссылка «Сравнить версии материала и теста» открывает таблицу различий двух сохранённых снимков, включая изменения вопросов/вариантов/баллов. Доступ требует разрешения просмотра версий; сравнение не изменяет историю и не начисляет баллы.

Каждое сохранение создаёт новую `MaterialVersion` и новые `MaterialQuestion`, а старые остаются неизменными. Скрытая версия формы предотвращает потерю изменений из другой вкладки. Прохождение остаётся единственным на стабильный ID материала; изменение стоимости или вопросов не выдаёт повторную награду. Канонический `ochakovo-history` сохраняет совместимость с `history-1`, 30 баллами и прежним прогрессом: его нельзя переводить во внутреннюю аудиторию или архивировать. Архивация других материалов скрывает их от читателей, сохраняя историю.

## Создание уровня

1. Создайте уровень, выбрав одну из шести серверных механик. Укажите постоянный ID, заголовок, условия, направление, баллы и связь с карьерным предложением. После создания ID и семейство в форме не меняются.
2. Заполните структурный конструктор задачи. Для автоматизации это поток и доступные блоки; для механики — поле, валы и разрешённые ременные связи; для лаборатории — образцы, исследования и наблюдаемые свойства; для склада — партии, резерв, заказ, геометрия палеты и склад; для истории — вопросы/варианты; для смены — показатели с рядами, схема, журнал, проверки, факты, варианты вывода и исследовательские подсказки.
3. Настройте оформление: семантические роли → ID спрайтов, а при необходимости — декоративную сцену с размерами и объектами. Публичная задача содержит только декларативные данные, не программные выражения.
4. Добавьте объекты сцены: отдельный спрайт либо повторно используемый модуль со слотами, размеры, позицию, поворот и слой. Переопределение слотов связывает ID слота с ID другого спрайта. Слот с ролью становится оформлением интерактивной сущности; её позиция определяется геометрией задачи. Пустая роль означает декорацию с заданной позицией. Например `source`, `gear`, `sample:a`, `batch:a` соответствуют ролям текущих игровых интерфейсов.
5. История и симулятор смены требуют закрытого `RuleSet`. В истории это соответствие вопрос → вариант; в смене — проверяемый вывод, альтернативные достаточные пути фактов, причинные/противоречащие факты, последствия и распределение оценки. Правило не отправляется в браузер и копируется в опубликованную версию.
6. Добавьте хотя бы одно положительное и одно отрицательное проверочное решение. Для каждого примера используется настоящая серверная механика. Положительный пример доказывает решаемость; отрицательный должен отвергаться. Опубликовать задачу с неработающими примерами, отсутствующими сущностями или несогласованным закрытым правилом нельзя.
7. Сохраните черновик, откройте ссылку предпросмотра. В iframe работает тот же React-рендерер игр. Проверка решения идёт через защищённый серверный endpoint с CSRF; баллы не начисляются, прогресс участников не меняется. Затем нажмите «Проверить и опубликовать новую версию».

Ссылка «Сравнить опубликованные версии» показывает различия снимков уровня. Без разрешения на приватные правила закрытая оценка и fixtures скрыты; чтение версий требует отдельного разрешения.

Сохранение черновика не изменяет активную публикацию. Публикация создаёт неизменяемый `LevelVersion`: публичная задача, закрытое правило и проверочные примеры. Мини-приложение читает ровно этот снимок; правила оценки берутся из той же версии, даже если редактор публикует следующую параллельно. Архив скрывает уровень, но сохраняет прохождения и баллы. Один стабильный ID уровня означает одну награду: для другой учебной задачи создавайте новый ID. Изменение ID образцов, фактов или геометрии в новой версии может сделать старый незавершённый черновик несовместимым; проверяйте совместимость перед публикацией.

## Спрайты и модули

В «Игровых спрайтах» загружаются PNG/JPEG/WebP до 10 МБ и 32 млн пикселей. Файл проверяется декодером; SVG с пользовательским кодом не принимается. Стартовые встроенные ресурсы остаются локальными. Спрайт, используемый опубликованным снимком, нельзя заменить, изменить его размеры или выключить: создайте новый ID, чтобы старые публикации сохраняли вид.

«Модуль сцены» задаёт габариты и слоты: ID, спрайт, роль, локальные координаты, размеры, поворот и слой. Сохранённые экземпляры компилируются в плоскую декларативную сцену при проверке и публикации. Слоты и объекты ограничены по количеству; размеры и координаты должны быть конечными числами и находиться в пределах сцены. JS/Python, внешние URL и HTML в композициях отсутствуют.

`GET /api/game-assets` возвращает безопасный публичный манифест. Новые файлы доступны через `/api/game-assets/<id>/`. Клиент принимает только локальные пути манифеста и добавляет ресурсы в реестр рендерера; новый ID спрайта не требует изменения TypeScript.

## Источники и запуск

Модели, формы, валидация, сервисы, шаблоны и редактор: `backoffice/content/`. `python manage.py seed_content` идемпотентно переносит начальные 6 семейств, 15 уровней, 16 отдельных спрайтов/модулей, 3 материала, карьерные предложения и награды из репозитория. Существующие редакторские записи не перезаписываются. На переносимой базе сначала выполняется импорт истории пользователей, затем общий bootstrap; не заполняйте таблицы целевой базы до импорта.

`server/catalog_store.py` читает актуальные опубликованные записи PostgreSQL без кеша и без отката к файловому каталогу, когда Django настроен. Приватные данные находятся только в `LevelVersion.private_rule`/`fixtures` и не включаются в публичный каталог. Файловые данные допустимы лишь для изолированных старых тестов без настроенного Django.

Проверки: `DJANGO_TEST_DATABASE_NAME=test_ochakovo_content .venv/bin/python manage.py test backoffice.content --noinput`; `npx tsc --noEmit`. Предпросмотр использует `game-preview.html` и `src/games/adminPreview.tsx`; продакшен-сборка должна включать этот entrypoint вместе с основным приложением.

Обновление схемы ORM и регистраций админки: `.venv/bin/python scripts/export-admin-schema.py`. Единственный выходной файл — `docs/django-models.json`; SQL и выполнение default-функций запрещены, записи пользователей не читаются.
