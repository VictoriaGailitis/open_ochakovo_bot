# Игры «Очаково: изнутри»

Реализованы четыре самостоятельные игры по три уровня, исторический тест и два исследовательских варианта симулятора «Разберись в смене».

`src/games/Games.tsx` экспортирует `GamePlayer`. Общая оболочка принимает задание каталога, сохранённый JSON-черновик, callback сохранения, серверной проверки, перехода к профессии и выхода. Все ответы проверяет backend; интерфейс не начисляет баллы самостоятельно. Повторное выполнение доступно без повторного начисления.

## План и механики

| Игра                  | Действия                                                                                                  | Проверка / черновик                                                                                                |
| --------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Сигнал → действие     | Добавление и удаление блоков, выбор условия и выхода, изменение порядка, пошаговая трасса пробного потока | `rules: [{condition, output}]`; первое совпавшее условие определяет выход                                          |
| Передай движение      | Установка и снятие шестерён на сетке, пробный запуск с направлением вращения каждого связанного узла      | `gears: [{x,y}]`; непрерывность цепи, смена направления при зацеплении                                             |
| Лабораторный детектив | Выбор исследований, раскрытие свойств, справочник, ручное исключение, выбор образца и доказательств       | `sampleId`, `evidence`; доказательства однозначно выделяют образец; черновик также хранит `revealed`, `excluded`   |
| Собери и доставь      | Выбор доступных партий, поворот и размещение фигур на площадке, маршрут по соседним клеткам склада        | `placements: [{batchId,x,y,rotated}]`, `route: [{x,y}]`; резерв, границы, пересечения, комплектность, достижимость |
| Исторический тест     | Последовательный выбор ответов, возврат к вопросу, источники                                              | `answers: {questionId: optionId}`, сохранённый `index`                                                             |

Игровые controls работают касанием и клавиатурой (Tab, Enter, Space для штатных элементов). Drag-and-drop не обязателен. Для сеток каждая клетка имеет координатную подпись. Анимация учитывает `prefers-reduced-motion`. Нет таймера, который давал бы преимущество в баллах.

Черновик сохраняется после 650 мс без изменений, операции записи выполняются последовательно. При выходе и перед серверной проверкой ожидается запись последнего состояния. При уходе через общую навигацию cleanup также сохраняет последнюю правку; `pagehide` запускает сохранение при перезагрузке. Ошибки сохранения видны, доступен повтор. Результат содержит объяснение, начисление/повтор и переход к связанному карьерному направлению.

## Макеты

High-fidelity контексты и screenshots получены через Figma для четырёх игровых экранов; локальные reference-материалы исключены из публикации. Исходные SVG скачаны из источников, указанных MCP, в `public/assets/games`. `ReferenceStages.tsx` сохраняет слои и геометрию статических иллюстраций; интерактивный режим открывается кнопкой основного действия. Палитра и типографика общие с приложением: Inter, paper `#FFF8F2`, red `#D50032`, stage `#361822`, blush `#FCE8EE`.

Контекст исторического теста не получен: Figma MCP вернул ограничение Starter plan. Тест использует общие токены и компоненты; это ограничение сверки именно этого экрана.

## Проверки

`npx tsx --test src/games/mechanics.test.ts` проверяет приоритет signal-правил, отсутствие маршрута при непокрытом условии, все три варианта signal, смену вращения и разрыв цепи, поворот фигуры, выход за границы, пересечение, резерв и допустимость маршрутного шага. Серверные тесты отдельно проверяют авторитетную валидацию, начисление и сохранение.

Полный UI-проход через CUA выполнен для всех 13 уровней на локальном API отдельным тестовым пользователем: все решения приняты сервером, итоговый баланс 630. Проверены поворот упаковок, сохранение ответа при немедленном hard reload до debounce, повтор теста без нового начисления и доступное управление Enter. Четыре статические игровые иллюстрации визуально сверены в браузере; исправлено позиционирование Figma contents-групп в лабораторной сцене. Временный тестовый harness после проверки удалён.

## «Разберись в смене»

`ShiftGame` — самостоятельная оболочка симулятора. Обзор содержит 12 показателей в сетке 3 × 4. У каждого показателя есть текущий и предыдущий снимки, график с реальными интервалами времени и таблица исходных измерений. Схема, события смены и результаты проверок доступны в произвольном порядке. Открытие материала само по себе не закрепляет его и не приносит баллы.

Игрок вручную закрепляет факты из показателей, динамики, схемы, деталей событий и проверок. Наблюдение сохраняет канонический источник, время и факт, а также пользовательскую заметку. Заметку можно редактировать, наблюдение — удалить. Удаление также убирает ссылку из оснований вывода. Технический предел — 32 наблюдения; требования выбрать ровно определённое число карточек нет. Рабочая гипотеза сохраняется отдельно и не оценивается автоматически.

Конструктор вывода содержит наблюдаемое изменение, объяснение, выбранные основания из своих наблюдений, безопасный следующий шаг и ответственного. До отправки доступны нейтральные критерии и исследовательские вопросы. Сервер принимает разные достаточные пути, проверяет противоречия и сохранённость оснований. Пример разбора и последствия появляются после принятого решения. Первое завершение варианта даёт 30 баллов, повтор — тренировку без нового начисления; скорость не учитывается.

Черновик включает открытый экран, выбранный материал, гипотезу, наблюдения, редактируемые заметки, поля конструктора и основания. Изменённый снимок получает монотонную ревизию один раз; повтор записи, уход со страницы и перезагрузка используют ту же ревизию. Неизменённая старая вкладка не может затереть более новую запись другой вкладки. При отклонении устаревшего сохранения редактор восстанавливает серверный черновик, если пользователь не успел внести более новую локальную правку. Новая правка сохраняется в редакторе, конфликт явно обозначается.

Визуальная структура перенесена из актуальных high-fidelity контекстов Figwright. Иллюстрация соединения на схеме использует исходный SVG; графики, значения и состояния узлов строятся по данным текущего варианта. Частные ссылки, идентификаторы и reference-материалы исключены из опубликованных исходников.

Проверки `shiftMechanics.test.ts`: пустое начало без подсказанных оснований, каноническое восстановление фактов, удаление связанных оснований, редактирование заметок, отсутствие ограничения в пять карточек, графики со стабильными значениями, неравными временными интервалами и ошибочными метками времени.

Дополнительно проверен серверный рендер всех 20 экранных состояний двух вариантов: обзор с 12 карточками, детали метрик, схема, журнал, событие, проверки, отдельная проверка, наблюдения, конструктор и критерии. Отдельно подтверждены точная позиция временной подписи графика и отсутствие предупреждений React в SVG-подсказках.

`draftClock.test.ts` проверяет неизменённую фоновую вкладку, повторные записи снимка, порядок очереди, восстановление серверной ревизии и новую правку после конфликта.
