# Размещение «Очаково: изнутри» в VK Mini Apps

Приложение VK уже создано: **54850900**, адрес запуска — https://vk.com/app54850900.
На 24 октября 2026 года подготовлены файлы размещения; публичный сервер, домен и реальный вход VK ещё не подключены.

Проверено локально: сборка Vite, 26 Python-тестов и 12 TypeScript-тестов; сборка Docker-образа; запуск Compose с Caddy на локальном HTTP; проверка размещения через `check:deployment`; вход с синтетической подписью VK, сохранение профиля и отклика, пересоздание контейнера и восстановление данных из volume. Публичный TLS-сертификат и VK Bridge в реальном клиенте ещё не проверены.

## Выбранная схема

Один Linux VPS с Docker Compose: Caddy принимает HTTPS и передаёт запросы контейнеру приложения. В нём находятся собранный React-интерфейс и Python API. SQLite хранится в постоянном Docker volume `ochakovo_app_data`. Сертификаты Caddy тоже сохраняются между обновлениями.

Для начального тестового запуска подойдёт VPS с 2 ГБ RAM и 10 ГБ диска; это стартовая оценка, а не результат нагрузочного теста. Сборка интерфейса выполняется на сервере. Нужны публичный IP, домен/поддомен и входящие TCP 80/443 (UDP 443 необязателен). Python и Node на сервере устанавливать отдельно не нужно.

VK размещает статические файлы через VK Mini Apps Deploy. Этому проекту также нужен Python API с постоянной базой. Поэтому подготовлен единый внешний HTTPS-адрес: он сохраняет текущие пути `/api` и `/assets` без дополнительных CORS-настроек. Токен `MINI_APPS_ACCESS_TOKEN` для этой схемы не требуется.

## Что нужно от владельца

1. Создать VPS с Docker Engine и Compose либо предоставить уже доступный сервер. Для настройки нужны адрес, SSH-пользователь и доступ через локальный SSH-ключ. Пароль учётной записи VK не нужен.
2. Выбрать домен или поддомен и направить его A-запись на IP VPS. Если есть AAAA, IPv6 тоже должен вести на этот VPS; лишнюю AAAA следует убрать. Купить сервер и домен нужно в своём аккаунте.
3. Получить **защищённый ключ приложения 54850900** в настройках VK. Он нужен только серверу для проверки подписи параметров запуска. Не путать с сервисным ключом доступа или пользовательским access token.
4. На сервере ввести ключ через команду ниже либо сохранить его в приватный `.env.production`. Не включать ключ в `VITE_*`, Git, клиентский код или сообщение в чате. Ключ HR-кабинета создаётся автоматически.

## Запуск на сервере

Скопировать текущую папку проекта на сервер **вместе с незакоммиченными изменениями**. Не переносить `node_modules`, `dist`, `.git`, `.data` и `.env*` с локальными данными. Файл `.env.production.example` можно переносить. Простое клонирование репозитория не включает текущие локальные изменения.

Из корня проекта на сервере (заменить `mini.example.ru` на выбранный домен):

```sh
python3 scripts/setup-deploy.py --domain mini.example.ru --app-id 54850900
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production ps
```

Скрипт скрыто запросит защищённый ключ VK, сгенерирует независимый ключ HR и создаст `.env.production` с правами `600`. Повторный запуск не перезаписывает файл. Все секреты передаются только работающему серверу, сборка фронтенда их не получает. Не публиковать вывод `docker compose config` или `docker inspect`: он может содержать переменные с ключами.

Caddy автоматически получает HTTPS-сертификат после корректной настройки DNS и доступности портов 80/443. API-порт 3001 наружу не открыт. Демовход в Compose принудительно выключен. Access log с параметрами запуска VK не включён.

Проверка с локального компьютера, где есть Node:

```sh
npm run check:deployment -- https://mini.example.ru
```

Команда проверяет API, настройки VK, отключённый демовход, отклонение поддельной подписи, защиту профиля и HR, доступность HTML/JS/CSS и заголовки, влияющие на iframe. Реальный вход VK эта проверка не заменяет.

## Настройки VK

В кабинете приложения **54850900** открыть раздел размещения. В поля URL для мобильного приложения, мобильной версии сайта и веб-версии указать одинаковый адрес:

```text
https://mini.example.ru/
```

Если включён режим разработки, указать этот же URL в соответствующих полях для разработки. Сначала проверить приложение своим аккаунтом администратора. При готовности включить доступ пользователям и заполнить необходимые поля кабинета/модерации. Названия полей сверить с текущим интерфейсом VK.

Открывать для проверки именно https://vk.com/app54850900 (также из приложения VK на телефоне). Прямая ссылка на домен без подписанных параметров VK должна показывать отказ во входе.

Проверить: завершение загрузки, заполнение вымышленного профиля, прохождение уровня, сохранение баллов после переоткрытия, отклик и его появление в HR. Не передавать URL с `sign` другим людям. Кабинет HR доступен по `https://mini.example.ru/#/admin`, ключ — `ADMIN_TOKEN` из приватного `.env.production`.

## Обновления и резервная копия

После переноса обновлённого исходного кода:

```sh
docker compose --env-file .env.production up -d --build
```

Не использовать `docker compose down -v`: это удаляет volumes вместе с базой и сертификатами. Обычная пересборка приложения сохраняет базу.

Сделать согласованную SQLite-копию (команды из корня проекта на сервере):

```sh
docker compose --env-file .env.production exec -T app python -c "import sqlite3; source=sqlite3.connect('/app/.data/ochakovo.sqlite3'); target=sqlite3.connect('/app/.data/backup.sqlite3'); source.backup(target); target.close(); source.close()"
mkdir -p backups
chmod 700 backups
docker compose --env-file .env.production cp app:/app/.data/backup.sqlite3 ./backups/ochakovo.sqlite3
chmod 600 backups/ochakovo.sqlite3
```

Копия содержит пользовательские данные, её следует хранить приватно и отдельно от VPS. Эта команда создаёт одну копию; расписание резервного копирования нужно настроить на выбранном хостинге.
