# Проверка Django-админки и PostgreSQL — 25 октября 2026

Мини-приложение и кабинет команды работают через Django 5.2/Unfold с общей PostgreSQL 16. Проверен объединённый код админки и актуального `main`, включая уже опубликованные коммиты параллельных задач по сканеру и чтению материалов. Изменения админки сохранены отдельными коммитами; неопубликованные правки других задач не включались. Реальный публичный VK-сервис в этой проверке не разворачивался.

## Автоматические проверки релизной копии

- `npm test`: **110 legacy Python + 94 Django/PostgreSQL + 65 TypeScript = 269**, все PASS. SQLite здесь используется только временными legacy-тестами и как источник теста импорта.
- `npm run build`: TypeScript и обе production-точки входа Vite (`index.html`, `game-preview.html`) — PASS.
- Django `check` и `makemigrations --check --dry-run`: PASS; схема соответствует сохранённым миграциям.
- Проверены персональные роли и отдельные права на чувствительные данные, фильтрованный CSV с защитой от формул и аудитом, история согласий, назначения наставников, подтверждение найма и выдача мерча, компенсации баллов.
- На реальном PostgreSQL проверены однократные начисления и конкурентные заявки разных пользователей на последнее место/последнюю награду. Карьерное предпочтение практиканта сохраняется как INTEGER 0/1; опросы и предпочтения не раскрываются наставнику.
- Конструкторы проверяют материалы, тесты, медиа, модульные сцены и шесть игровых механик. Публикация уровня требует принимаемого и отвергаемого решения. Версии неизменяемы; сравнение и приватные поля ограничены правами.
- После слияния проверены карьерные пояснения в опубликованных версиях и сроки отклика длиннее 40 символов. Черновик и завершение передают `contentVersion`; старая версия после перепубликации получает 409 без записи прогресса/баллов. Каноническая история остаётся в материалах, новые авторские history-уровни доступны отдельно.
- Генератор ORM-манифеста выполнен дважды с одинаковым результатом: 54 модели/таблицы, 368 полей, 46 регистраций Unfold. SQL запрещён при генерации; callable defaults/choices не исполняются.

## Браузер → Django → PostgreSQL

- В админке создана тестовая активность: QR назначен автоматически без ручного поля. Скачанный PNG загружен в миниапп; employee-баланс вырос с 20 до 25. Повтор показал «Уже отмечено», сохранив 25. После проверки активность отключена.
- Через структурный конструктор создан черновик материала с вопросом, двумя вариантами, правильным ответом и пояснением. Предпросмотр подтвердил ответ без начисления баллов. Тестовый материал архивирован.
- Игровой предпросмотр использует тот же React-движок: алгоритм сортировки прошёл серверную проверку, экран показал +0 баллов. Пользовательский прогресс не изменялся.
- Проверены экран сравнения сохранённых версий и схема смены с четырьмя доступными потоками. Соединения строятся из данных уровня; координаты, формат и вид узлов согласованы с конструктором.
- Рабочий стол Unfold отображает только разрешённые разделы; старые неизвестные статусы откликов сохраняются отдельным счётчиком.

## Миграция и восстановление

Перенесено 397 исходных строк из всех 31 таблицы прототипа. Для исторической регистрации без определения создано неопубликованное архивное мероприятие. Исходный SQLite-файл сохранён; importer открывает источник read-only и отказывается перезаписывать непустые целевые таблицы. Резервная копия и checksum создаются сразу с правами 0600, новый приватный каталог — 0700.

После миграции сделан `pg_dump -Fc` с exported REPEATABLE READ/READ ONLY snapshot. Копия восстановлена в отдельную пустую тестовую базу: совпали количества строк всех 45 доменных таблиц, SHA256 каноничных строк всех 31 core-таблицы и количества записей шести таблиц авторизации Django. Временная база удалена; рабочая база не изменялась при проверке. Значения профилей, токенов и хешей не публиковались.

После объединения новых текстов dry-run команды `sync_seed_copy` подтвердил 21 нетронутое стартовое определение. Явное применение обновило 15 уровней и 6 предложений; повтор показал 21 unchanged и 0 новых изменений. Уровни получили новые версии, существующие баллы и пользовательский прогресс сохранены.

## Production-контейнер

Финальный образ собран из той же релизной копии. Выполнены **54 HTTP smoke-проверки + 16 проверок `check:deployment`**, все PASS: migrations, идемпотентный bootstrap, collectstatic (162 ресурса), три Gunicorn worker, запуск от `appuser`, состояние healthy, HTML/JS/CSS приложения и админки, 16 спрайтов, API и игровой preview.

За доверенным HTTPS proxy собственный Origin принимается, чужой получает 403. DEV_AUTH выключен; демонстрационный вход получает 403, поддельный запуск VK — 401. Старый `/api/admin/*` возвращает 410 даже со старым общим ключом; Django cookies не дают доступ к bearer API. Для проверки использовалась заведомо фиктивная VK-конфигурация. Реальный VK Bridge, домен, TLS и рабочие VK-ключи проверяются отдельно в целевом окружении.

Временные контейнеры, базы и сети проверки удалены. Локальный PostgreSQL и его volume сохранены. Приватные URL дизайна, базы, файлы доступа, QR-пейлоады и резервные копии исключены из публикации. Запуск и операционные ограничения описаны в [runbook](django-admin.md).

## Проверка интерфейса

Через браузер и настоящий локальный API пройдены:

1. Первый вход, оба шага профиля и восстановление после перезагрузки.
2. Предложение по выбранному интересу, подтверждение отклика и отображение принятой заявки. Заявка дополнительно найдена через защищённый API HR.
3. Карточка события, подтверждение записи, отображение своей записи и отмена. Свободные места меняются с 20 до 19 и обратно до 20.
4. Все три уровня каждой из четырёх игр и исторический тест — всего 13 завершений отдельным тестовым пользователем, итог 630 баллов.
5. Трасса правил, размещение шестерён, исследования и доказательства, резерв партии, поворот упаковки и маршрут склада.
6. Сохранение выбора при немедленной перезагрузке до debounce; повтор теста без нового начисления; управление Enter.
7. В составе приложения — завершение уровня, изменение баланса с 0 до 50, демонстрационный обмен, списание до 0 и уменьшение остатка награды на один.
8. Основная навигация, доступ к профилю и баллам, локальные ассеты и мобильная компоновка шириной 390 px. Дополнительно проверены главная, игровая иллюстрация и интерактивная сетка на ширине 320 px: горизонтального переполнения нет.
9. Оба варианта «Разберись в смене» пройдены через настоящий API: первый — с основанием из журнала, второй — из независимой проверки подачи. Баланс тестового профиля вырос с 0 до 60; повтор первого варианта оставил баланс 30. Необоснованный вывод отклонён. Проверены добавление, редактирование и удаление наблюдения со снятием его из оснований, нейтральные критерии до отправки, восстановление после немедленной перезагрузки до debounce, динамика графика, схема и возврат в каталог. Схема проверена на ширине 320 px без переполнения. В двух вкладках подтверждено, что перезагрузка неизменённой старой вкладки не стирает свежую заметку другой вкладки. Консоль браузера без ошибок и предупреждений.

10. Регистрация: ввод даты 17-летнего пользователя до заполнения контакта открывает отдельный экран с грустной открывашкой. Исправление даты возвращает фокус в поле и сохраняет введённые поля. Дата ровно 18 лет разрешает оба шага, сервер сохраняет профиль и открывает главную. Прямые ссылки в задания и карьеру, а также перезагрузка не дают доступа без зарегистрированного профиля. На ширине 320 px нет горизонтального переполнения, кнопки доступны касанием. Консоль браузера без ошибок и предупреждений.

11. QR: вход из раздела «События» и из карточки мероприятия. Два настоящих QR-изображения распознаны браузером и отправлены в API: +15 и +20, баланс 35. Повтор первого QR оставил баланс 15; чужой QR не открыл ссылку и не дал баллов, неизвестный код показал ошибку с повтором. Карточка показывает 2 из 2 выполненных активностей; после перезагрузки статусы сохранены. В истории ровно два начисления. Запись не создавалась, все 30 мест остались свободными. На ширине 320 px карточки и сканер без переполнения, камера не запускается при открытии страницы. Консоль браузера без ошибок и предупреждений.

Тестовые анкеты и операции хранятся только в локальной базе, исключённой из репозитория. Временные игровые стенды, стенд QR и файлы с тестовыми QR удалены.

## Что требует внешней настройки

- Физическая камера и `VKWebAppOpenCodeReader` на устройстве требуют ручной проверки. Проверен реальный путь QR-изображение → декодер → API → данные → интерфейс; доступ к камере устройства во время проверки не запрашивался.
- Запуск внутри реального VK-клиента: нужны ID приложения, защищённый ключ и настроенный HTTPS URL. Проверка криптографии автоматическими тестами не заменяет проверку VK Bridge на устройстве.
- Реальные вакансии, события, награды, условия участия и выдачи должны быть подтверждены компанией.
- Перед обработкой реальных данных необходимы утверждённая политика и процедуры отзыва согласия/удаления.
- Профессиональное содержание учебных моделей требует проверки экспертами. Игры не определяют пригодность кандидата.

Работа с дизайном и состояние подключения Figwright описаны в `docs/design.md`. Приватные адреса и исходные выгрузки дизайна не публикуются.
