# Операционная админка

Все операции работают в PostgreSQL и используют транзакции Django. `MiniUser` и `StaffCredential` — аккаунты мини-приложения, они не дают права входа в Django admin.

После применения миграций выполните `python manage.py setup_backoffice_roles`. Команда обновляет группы `HR`, `organizer`, `coordinator`, `technical_admin`, `content_editor`, `game_editor`, но не создаёт администраторов и не назначает им группы. Авторизованный суперпользователь назначает нужные группы отдельным Django-пользователям.

Права на личные опросы практики, карьерные предпочтения и обезличивание выдаются отдельно: соответствующее `operations.*` разрешение и стандартное право просмотра модели. В базовых группах этих прав нет. Организатор получает ID участников; данные анкеты видит HR.

Экспорт откликов — отдельное разрешение `operations.export_candidate_data`, которого нет в базовых группах. Дополнительно нужны `operations.view_candidate_pii` и `core.view_application`. Кнопка CSV сохраняет текущие фильтры и поиск, выгружает снимки анкет из откликов (до 10 000 строк), экранирует значения, которые Excel может принять за формулы, и записывает ID/число строк в аудит без значений анкет. Ответ не кешируется.

Анкета исправляется с основанием, проверкой 18+ и сохранением исходных сведений о согласии. Снимок отклика не меняется вслед за анкетой. Обезличивание по запросу субъекта — отдельное исключение: очищает личные поля и в текущей анкете, и в снимках, сохраняет исторические сведения о согласии и отзывает API-сессии. Новое пользовательское согласие записывается событием `granted` с `actor=None`; перенос исторического факта — событием `observed`.

Пароль сотрудника вводится только в поле нового пароля и сохраняется PBKDF2-хешем. Изменение пароля, логина, роли или отключение аккаунта отзывает сессии. Действующая практика препятствует смене роли. Практику нельзя переносить другому пользователю; периоды проверяются по целям и встречам. Входящие координатора отделены от обращений наставнику, ответы используют контроль версии.

Имя выданного сотрудника можно исправить в той же форме: меняется только `fullName` его staff-профиля, остальные поля сохраняются. Пустое поле сохраняет прежнее имя; значение имени в аудит не записывается. Анкеты кандидатов эта операция не меняет.

Мероприятия редактируются структурированными полями, активности — внутри мероприятия или отдельно. QR создаётся автоматически при первой записи активности и остаётся стабильным. Защищённая страница позволяет скачать PNG/SVG и распечатать код; в публичном каталоге токена нет. Изменение аудитории после появления участников запрещено, вместимость не может стать меньше подтверждённых записей. Записи сериализуются блокировкой мероприятия.

Подтверждение найма выполняется отдельным POST-действием в отклике с рекомендацией. Оно создаёт единственное право на мерч, без баллов. Физическая выдача оформляется в «Выдаче наград»: выбирается один обмен либо одно реферальное право. Повторная выдача и редактирование выданной награды запрещены.

Начисления, выполнения, снимки, административный аудит и история доступны только для чтения. Исправления баллов оформляются компенсирующей операцией с основанием и ключом идемпотентности. Блокировки пользователя и ключа предотвращают двойное начисление; отрицательный итоговый баланс запрещён. Аудит содержит идентификаторы и имена изменённых полей, без паролей, QR-токенов, ответов опросов и значений анкеты.

Проверки: `python manage.py test backoffice.operations` (нужен PostgreSQL с правом создания отдельной тестовой БД).
